# 环境采集：开工前问清这九件事

> SKILL.md「开工第 0 步」的执行清单。**别假设环境长什么样**——每个团队的靶场都不一样。
> 采集一次，沉淀进 `project-anchors.md`，以后每次验收直接引用。

---

## 一、怎么问

### 对 AI 自己

拿到"验收这个功能"的指令后，**先不要开始读代码**。第一件事是把下面九类过一遍：

- 已经知道的（`project-anchors.md` 里有、会话上下文里有）→ 直接用，不重复问
- 不知道的 → **一次性列成清单问用户**，别挤牙膏式一条条问

**问法示例**（一次性抛出，让用户一次答完）：

```
开工前先确认靶场，麻烦一次性给我这几项（有现成的就贴给我，没有的我按缺省降级）：

【代码】本地副本路径？远端编译机上的副本路径？两者是同一份还是需要同步？
【连接】编译机/跳板机怎么连（ssh 目标、免密还是密码、口令放哪个环境变量）？
【实例】测试用哪个区服/进程？测试角色 uid？有没有跨服/分区这类多实例？
【消息】模拟客户端的工具在哪、怎么发一条协议、怎么收主动推送？
【GM】  GM 命令怎么发（命令行还是网页台）？命令清单在哪个文件？能不能转发到别的实例？
【日志】日志根路径与命名规则？有哪些 kind（主日志/告警/指令/框架错误）？怎么定位某实例跑在哪台机器？
【数据】数据库/缓存怎么连？哪些库/表是权威态（不是镜像）？
【发布】编译命令？发服命令？会不会影响别人正在用的环境？
【需求】需求文档在哪？怎么读到最新版？
```

### 对用户（如果你是提需求的那个人）

至少给出这四样，其余可以现场摸索：

1. **测试角色和实例**（uid / 区服 / 进程号）
2. **怎么发一条消息**（工具路径或命令）
3. **怎么查服务端真实状态**（GM 命令或数据库）
4. **需求文档链接**

> 少给一样，验收就会在某个环节降级成"读码推断"，结论强度掉一档——这没关系，
> 但**必须在报告里写明降级在哪**。

## 二、九类信息详解

### 1. 代码

| 要问 | 为什么 |
|---|---|
| 本地副本路径 | AI 改代码 / 生成探针落在这里 |
| 远端副本路径 | 编译、运行发生在这里 |
| 两者是否同源 | 同源（网络盘/共享目录）→ 改完立即可见；不同源 → 每次要同步，**忘了同步 = 跑的是旧代码** |

⚠️ **"改了没生效"的第一嫌疑人永远是这里**：本地改了、远端没同步、或者发服发到了别的实例。

### 2. 连接

| 要问 | 为什么 |
|---|---|
| 跳板机 / 编译机地址 | 一切远端操作从这里走 |
| 认证方式 | 免密 key / 密码 / 堡垒机 |
| 口令来源 | **必须走环境变量，不许写进文件或代码** |

⚠️ 常见坑：同一台机器可能有**多个身份**，权限不同（一个能写工作副本、一个只读）。
先问清楚哪个身份能干什么，别用只读身份去编译然后误判"工作副本丢了"。

### 3. 靶场实例

| 要问 | 为什么 |
|---|---|
| 测试区服 / 进程 | 消息发到哪 |
| 测试角色 uid | 用哪个号跑 |
| 多实例情况 | 有没有跨服 / 分区 / 多节点——**有的话，单实例跑通 ≠ 功能跑通** |

⚠️ 多实例是验收的**主要复杂度来源**：状态可能被镜像、权威台可能不是本机、实例之间可能互相让位。
有跨进程结构就先读 `target-range-adapter.md` 的「跨进程取证」一节。

### 4. 消息探针（模拟客户端）

| 要问 | 为什么 |
|---|---|
| 工具在哪 | 没有它就只能 GM 驱动 + 读码 |
| 怎么发一条 CS | 发消息的最小命令 |
| 怎么收 SC 和主动推送 | **主动推送只能从这里拿到**，GM 和日志都看不到玩家视角的推送 |
| 协议定义怎么更新 | 改了协议要重新生成什么（否则新字段全是空/nil） |

### 5. GM 通道

| 要问 | 为什么 |
|---|---|
| 怎么发 | 命令行 / 网页台 / 管理后台 |
| 命令清单在哪 | 新增 GM 时知道往哪加 |
| 能否跨实例转发 | 多实例功能的常见操作方式 |
| 回执语义 | **"OK" 只代表参数解析通过，不代表生效** |

⚠️ 跨实例 GM 的第一个参数常常是"发给哪个实例"，不是"本机属于哪个实例"——这类约定必须问清楚，猜错等于测错对象。

### 6. 服务器与日志

| 要问 | 为什么 |
|---|---|
| 日志根路径与命名规则 | 取证的第三路 |
| 有哪些 kind | 告警日志优先级最高，状态机不推进/结算失败基本都在那 |
| 怎么定位实例在哪台机器 | 日志往往不在编译机上，要跨机取 |

### 7. 数据

| 要问 | 为什么 |
|---|---|
| 数据库/缓存怎么连 | 造环境 + 核权威态 |
| 哪些库/表是权威态 | **镜像态和权威态可能不一致**，查错地方会得出相反结论 |
| 改前怎么留快照 | 能不能回滚、能不能重造 |

### 8. 发布（修复闭环的最后一环）

| 要问 | 为什么 |
|---|---|
| **代码根目录**（本地/远端是否同一份） | 改错副本 = 白改 |
| 编译命令 + 耗时 + 产物路径 | 不知道测的是不是新代码 |
| 发服命令 + 目标实例怎么传 | 发错机器 |
| **只发改动的进程** | 改一个服别全发，省半小时 |
| 启动校验在哪看 | 环境挂了还以为在测 |
| **落地判据**：怎么确认目标实例真换了新二进制 | 拿旧二进制测，结论全废 |
| **影响范围** | 会不会重启别人正在用的环境 —— **红级，必须问用户** |

### 9. 需求源

| 要问 | 为什么 |
|---|---|
| 文档在哪、怎么读最新版 | 「正确期望表现」的唯一权威来源 |
| 是否活文档 | 会中途修订——验收当天重读，不信旧摘录 |

## 三、产出：环境指纹

**每次验收生成一份，写进报告开头。** 没有指纹的结论无法判断适用范围。

```
ENV-<日期>-<序号>
代码版本   : <revision / 本次改动范围 / 分支>
二进制部署 : <部署时间，取自日志首行或发布记录>
环境名     : <dev / 云 / 外网 / 预发>
目标实例   : <区服 / 进程 / 多实例拓扑>
测试角色   : <uid / account>
关键数据态 : <名单是否已重建 / 角色是否已加载进内存 / 相关开关与阶段状态>
```

**为什么必须有**：同一个现象在不同环境下可能是不同的东西。指纹让"换个人、换台机器、换一天能不能复现"这个问题**变得可回答**——两份指纹不同的报告，本来就不该拿来互相印证。

**数据态那一行最容易被忽略，也最有价值。** 大量"看起来像 bug"的现象最后归到数据态：
角色没加载进内存（导致每场都缺阵重试）、名单没重建（导致档位全是 0）、包没发到那台机器（导致"功能没实现"）。
**先把数据态写清楚，能省掉一半无效排查。**

## 四、降级矩阵：缺什么会掉到什么程度

| 缺的能力 | 后果 | 降级做法 |
|---|---|---|
| 消息探针 | 无法验证玩家反馈路径 | 只能 GM 驱动 + 读码推断；**报告必须标注"未发协议"** |
| GM 通道 | 造不出可测状态 | 手动凑环境（慢、不可重复）；或只验不需要前置状态的分支 |
| 日志 | 异常无从取证 | 只能靠回包 + 数据库 |
| 数据库/缓存 | 核不了权威态 | 只能信 GM 回执（**回执 ≠ 生效，结论强度下降**） |
| 编译发布 | FAIL 无法闭环 | 出报告等用户发服；**"修完不复跑"要写进未完成项** |
| 需求文档 | 期望表现没权威来源 | 用户口述边界，覆盖面靠人记；**歧义项显著增多** |

**降级不是失败，隐瞒降级才是。** 缺什么、结论因此弱在哪，写进报告的"已知边界"。

## 五、分发：给别人用的时候

本 skill 设计成**方法层（可分发）+ 适配层（不外发）**：

| 文件 | 能不能对外分发 |
|---|---|
| `SKILL.md` | ✅ 可以 |
| `references/environment-intake.md`、`target-range-adapter.md`、`adversarial-scenarios.md`、各 `*-template.md`、`quick-checklist.md`、`example-walkthrough.md` | ✅ 可以（全部脱敏、不含项目常量） |
| `references/project-anchors.md` | ❌ **不外发**（含本团队真实路径、框架行为、工具入口） |
| `references/adapter-example.md` | ❌ 不外发（某团队的参考实现，含 IP/账号/专有命令） |
| `scripts/selftest.py`、`rsh.py`、`message_map.py`、`verify_report.py` | ✅ 可以（**已去掉所有团队默认值**） |
| `scripts/selftest.config.json` | ❌ 不外发（含你的地址与账号；只发 `selftest.config.example.json`） |
| `scripts/__pycache__/` | ❌ 删掉再打包 |

**打包命令示例**（排除适配层）：

```bash
cd ~/.claude/skills
zip -r adversarial-gameplay-acceptance.zip adversarial-gameplay-acceptance \
  -x "*/__pycache__/*" "*/project-anchors.md" "*/adapter-*.md" "*/selftest.config.json"
```

**对方拿到后怎么起步**：读 `SKILL.md` 末尾的「团队接入」四步——采集环境 → 填锚点 → 配脚本（或写自己的驱动）→ 开工。
