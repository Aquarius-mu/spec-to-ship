# 快速清单（10 分钟版）

完整流程（Step 0→7）适合功能开发完成后的正式验收。小改动、hotfix、时间紧迫时，用这份压缩清单过一遍——它保留了最容易出事的检查项，但**不能替代完整验收**，报告里要注明"仅快速清单"。

## 先过「提问闸门」（10 秒，能省掉用户大半火气）

要问用户之前，先确认：

- [ ] 案子正文、**画板**、**内嵌表**都查过关键词了吗？
- [ ] 配置表 / GM 公共参数查过吗？
- [ ] `python scripts/history_search.py "关键词"` 跑过吗？（命中 = 已决，不许再问）
- [ ] 它有合理默认值、且能低成本回滚吗？是 → 先做 + 标注假设，不要问。

**七路全空才许问**；只查到一半的，只问缺的那一个数。

## 先过「假 bug 四问」（30 秒，能省掉大半返工）

写任何一条 FAIL 之前先自问：

- [ ] **观测关**：我读到的这个值，是工具真实表达的吗？（窄整型被打成字节、回包被截断、一个码多处复用有歧义）
- [ ] **数据态关**：这个对象此刻真的处于我以为的状态吗？（没加载进内存、被上一步清空、异步还没落库、环境本来就缺）
- [ ] **时序关**：这个时刻真的落在我以为的窗口里吗？（窗口宽度不恒定、状态机只前进不后退、只改基准没重算）
- [ ] **局部性关**：我看的这一份 / 这台，是权威的那份吗？（多实例各持一份、查到的是镜像）

**四关全过，"这是代码 bug"才成立。** 破法都是**一次实验**，不是一次思考。

## 没有标准答案的，用关系验（别跳过）

战斗结果 / 匹配 / 排名 / 随机 / 战力 —— 没有"正确值"，但有**应有关系**：

- [ ] **确定性**：同输入跑两次，结果一致吗？
- [ ] **双视角对称**：A 看到"我赢了"，B 看到"我输了"吗？（不需要知道谁该赢）
- [ ] **守恒**：扣的 = 消耗的 + 退的？发的奖 = 配置数量？
- [ ] **保序/单调**：积分高的排名更靠前？等级高的战力不更低？
- [ ] **幂等**：重复 N 次 = 1 次？

## 必答题（每题都要有 文件:行号 才能算过）

**回包**
- [ ] 每条请求消息：所有分支（含异步成功路、异常路、空入参、循环全跳过的兜底）都恰好回一次应答？
- [ ] 有没有"提前返回但没回任何包"的路径？多层异步链深处 return 0 = 无痕吞包，逐层追到最终回包落点。
- [ ] 异常路回的是错误码还是"假成功包"？
- [ ] 应答字段：客户端要渲染的都填了吗？空列表/0 值时客户端显示什么？回包承诺的效果和回包同帧落地吗（展示值 ≠ 到账值 = P1）？

**时机与身份**
- [ ] 成功路径是改完状态之后才回包吗？
- [ ] 异步回调的应答发回给谁？发错人的可能性核对过吗（身份字段、循环变量、下标对齐、共用回包路由的多发起方）？
- [ ] 回调触发时玩家已下线/活动已结束，会怎样？活动结束后退出类操作（回城）还可用吗？
- [ ] 双端各算一遍的时间字段（剩余时间/到期/CD）时钟源统一吗？(时刻+时长)型操作终点校验过日边界吗？

**刷与绕**
- [ ] 去重/资格检查在发放**之前**吗？
- [ ] 连点两次：第二次被拦且玩家有反馈吗？
- [ ] 限制是服务端拦的，还是只靠客户端藏按钮/后台前端？GM 通道、直接发包能绕过吗？
- [ ] 上限/去重判据和"计数何时增加"逐字对齐吗？

**经济与配对**
- [ ] 扣费 ↔ 退款对称吗（折扣也对称）？预检查按折后量算吗？
- [ ] 作用集合对称吗（扣了 5 支编队，补的是同一集合吗）？
- [ ] 配对清理有没有藏在幂等 continue/早退分支里？释放键能区分新旧周期吗？
- [ ] 发奖失败会置"已领取"标记吗？（不许）
- [ ] 每条产生结果的路径（手动/到期/被动）都触发全部下游（排行榜、任务计数、埋点）吗？
- [ ] 每个状态写入点都有对应推送？推送字段包含刚改的字段？多通道投递（push+兜底队列）在线不重弹、离线不丢吗？
- [ ] 改持久化缓存标记了"已变更待落盘"吗？

**GM 链路**（功能可被 GM 触发/观测时）
- [ ] GM 指令构造的请求上下文字段和正常调用方逐字段一致吗？
- [ ] GM 回执成功有业务级证据吗（埋点/push/cache dump），还是只看了返回文本？
- [ ] GM 清/设的字段就是功能判读的那份数据吗？

**时机边界**
- [ ] 功能开启前就在线的玩家，开启后不重登能正常参与吗？
- [ ] 结束前一秒操作/回调回来时已结束，行为对吗？

**错误码**
- [ ] 新增错误码：客户端有文案吗？没有 = P1，写进需确认项。
- [ ] 会回给玩家的码，玩家能看懂下一步该做什么吗？哪些码是流程信号码（客户端据此走正常分支）？
- [ ] 关键失败出口有日志吗（一码多义 + 零日志 = 线上不可定位）？

**需求对照**
> hotfix 可跳过完整六维闸门，但必须写明"需求来源：<案子章节 / 用户口头 / 已决台账 D-xx>"，
> 且发现清单必须挂 RQ 编号或标"需求未写"——挂不上的，多半是需求本身漏了。

- [ ] 本次改动对应的需求条目是什么？案子没写、用户口头说的，记进已决台账，别下次再问。
- [ ] 从参考功能复制来的逻辑，逐条对照过新需求文档吗（含条件匹配语义，禁止从同构先例移植）？冲突以新文档为准。
- [ ] 任务计数挂对活动作用域了吗？同一目标的多种完成形态计数口径钉死了吗？
- [ ] 空配置字段的默认语义反直觉吗（空=1次 vs 空=不限）？
- [ ] **需求清单穷尽了吗？** ① 文档需求章节数 = RQ 组数（无跳号）② 每条 RQ 三列（实现位置/验证方式/证据）无空列 ③ 双向对账两个方向都出了清单。缺一不许出报告。
- [ ] **"配了数值就该生效"的需求**（加成/倍率/时长/概率/档位奖）：载体字段找到了吗？无效果与有效果两次读数差 = 配置值吗？到期/撤销后回退了吗？只确认"字段有值"不算验过。
- [ ] 配置条数核对走的是业务读取接口，还是自造解析二进制/序列化输出？后者容易读错层级得出"配置为空"的错结论。

## 最低限度实跑（有靶场就必须做，5 分钟）

> 用下面这些命令前，先照 `scripts/selftest.config.example.json` 配一次靶场；
> 没配就跑 `python scripts/selftest.py env`，它会直接告诉你缺什么。

**快速清单 ≠ 只读代码。** 上面那些问题有一半用一条消息就能问出答案，别用推演代替。至少跑这四条：

- [ ] `python scripts/selftest.py env` —— 链路通不通、协议是不是新鲜的
- [ ] 对本次改动的**主入口消息**发一条，回包内容对得上吗（`gen` → 改值 → `run`）
- [ ] 涉及状态变化的：用 GM 查一次服务端真实值，和回包里说的**一致**吗（回包说成功、状态没变 = P0）
- [ ] `python scripts/selftest.py log <zone> --svc game --kind alarm` —— 有没有新冒出来的告警

跑不了就写清卡在哪（环境缺数据 / 功能没部署），并标注"仅案头，未实跑"。

## 输出

快速清单的产出可以简化为：结论 + 需求对照（一行 RQ 或"需求未写"）+ 发现清单（P0/P1/P2，带 文件:行号 + RQ）
+ 需确认项 + 一行覆盖率声明（"仅快速清单，未做完整反馈路径表与场景卡"）。

交付前同样跑 `python scripts/verify_report.py 报告.md` 过一遍形式闸门。
