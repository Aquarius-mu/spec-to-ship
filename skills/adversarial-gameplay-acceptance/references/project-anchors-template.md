# 项目锚点记录（模板）

第一次在某个团队里跑本 skill 时，把下面两部分填完，另存为同目录的 `project-anchors.md`。
之后每次验收 Step 0 直接引用，不重复摸环境。**框架大版本升级 / 换靶场后要重新验证并更新。**

> ⚠️ 填好的文件含真实路径、账号、工具入口，属**适配层**——**对外分发 skill 时不要带它**。

---

## 第一部分：框架回包事实（必须回答的四个问题）

这四条决定"哪类检查可以放松、哪类必须加严"，**因项目而异，必须现场读框架代码验证**。

1. **同步失败回包**：消息处理器返回错误码时，框架会自动给客户端回错误包吗？回给谁？
   - 如果自动回：同步失败分支不会"点了没反应"，验收重点转为"错误码有没有玩家文案"。
   - 如果不自动回：每个失败分支都必须自己回应答，否则全是"玩家点了没反应"的 P0。
2. **异步应答身份**：异步回调里的应答，靠什么确定发给哪个玩家？会不会发错人？
   - 有没有"发起时快照请求身份、回调时恢复"之类的机制？自定义回调结构不走这套机制会不会绕过身份隔离？
3. **推送定位**：主动推送靠什么定位玩家？显式传身份还是依赖当前请求上下文？
   - 依赖当前上下文的推送，在跨异步边界后可能推错人。
4. **并发模型**：同一玩家的并发请求是串行处理还是并行？（决定双击竞态怎么分析。）

### 记录格式

```
N. <框架行为结论，一句话>
   证据：<文件:行号>
   推论：<对验收意味着什么——哪类检查可以放松、哪类必须加严>
   验证日期：<YYYY-MM-DD>
```

## 第三部分：落地判据（动作 → 怎么算真的生效了）

**命令返回成功只证明"参数解析通过"。** 把本项目造环境的每个动作，都配一个独立判据，
写死在这张表里 —— 每次造环境照着核对，而不是凭记忆觉得"应该好了"。

| 动作 | 判据**不能**是 | 判据**应该**是 | 备注（延迟 / 坑） |
|---|---|---|---|
| 发版 / 重启 | 脚本返回 0 | | 输出里哪个标志说明目标真的重启了？ |
| 编译 | 命令返回 0 | | 产物路径与时间戳 |
| 改时间 / 推阶段 | 回执 OK | | 要不要等一帧？会不会只改基准不重算？ |
| 塞数据 / 改配置 | 回执 set OK | | 落库是同步还是异步？等几秒？ |
| 发设置类协议 | 协议回 0 | | 对端从哪能看到"真的收到了"？ |

> 通用要求见 `target-range-adapter.md` §六。**这一栏留空的项 = 这个动作的生效无法验证**，
> 那它造出来的环境就不可信 —— 补上，或者明确标注该步骤结论不可靠。

## 注意

- 只记**验证过**的行为，不记猜测。每条必须有证据。
- 六件套里**没有**的项要写"没有"，并注明降级到哪一档（见 `environment-intake.md` §四降级矩阵）。
- 本文件属于团队资产，可以写真实路径——因此**不要**把填好的本文件对外分发；对外分发 skill 时只带本模板。
