# 验收报告模板（案头审计）

```markdown
# 对抗性业务验收报告：<功能名>

## 结论
<一句话：可上线 / 有 P0 阻塞 / 有 P1 建议修复>

## 0. 环境指纹
（本次结论成立的前提。格式见 environment-intake.md §三；缺这一节报告不予交付。）

- 代码版本   : <revision / 本次改动范围 / 分支>
- 二进制部署 : <部署时间；纯案头审计写"未部署，仅读码">
- 环境名     : <dev / 云 / 外网 / 预发>
- 目标实例   : <区服 / 进程 / 多实例拓扑；纯案头写"无">
- 测试角色   : <uid / account；纯案头写"无">
- 关键数据态 : <名单是否已重建 / 角色是否已加载 / 相关开关与阶段状态；纯案头写"未实测">

> 一句话：**这份结论换个人、换台机器、换一天，还能不能复现？** 上面就是答案的依据。

## 1. 框架机制确认
（本项目回包机制的真实行为，每条带证据。已有 project-anchors.md 且未过期时引用并注明。）
- 同步失败回包机制：…（证据 文件:行）
- 异步应答身份机制：…（证据）
- 推送定位机制：…（证据）

## 2. 需求输入闸门与需求对照

闸门：需求规格 `.tmpfiles/<功能>/需求规格.md` ｜ 六维就绪度 `<✓/△/✗ × 6>` ｜ 判定 `<通过/不通过>`
缺口：Q-xx 共 N 条（已分流：案子 A / 配置 B / 台账 C / 待问策划 D）

| RQ | 需求摘要（出处） | 实现位置 | 状态 | 结论 |
|---|---|---|---|---|
| R-01 | …（§x.y） | file:line | 已实现 | PASS |
| (—) | 需求未写但代码有：… | file:line | 加戏 | 待确认 |

> 只允许两种行：挂 RQ 的，或标"加戏/范围外观察"的。挂不上的不许进表。

### 2.1 需求穷尽性（三项都要填，缺一即未验收）

| 项 | 内容 | 判据 |
|---|---|---|
| 文档章节数 / RQ 组数 | 主案 §3.1→R-01~05；数值表 §8.1→R-40~44（并入同一体系） | 两数相等，跳号即漏节 |
| 三列闭合 | 每条 RQ 都要有：实现位置 / 验证方式 / 证据 | 空列数 = 0 |
| 双向对账 | 代码有文档无（加戏，待确认）｜文档有代码无（漏实现，缺陷） | 两个方向都出清单 |

## 3. 反馈路径表
（每个入口一张，格式见 feedback-path-table-template.md，覆盖全部分支）

## 4. 发现清单（P0 → P1 → P2）
每条：
- [RQ-xx | 需求未写] [文件:行号] 一句话代码事实。
  玩家场景：<玩家做了什么 → 屏幕出现什么 → 应该出现什么 → 为什么会误导/卡住>
  建议：<怎么改，或找谁确认>

## 5. 对抗场景卡结果
（十二类逐条给结论：已验证无问题 / 发现问题#编号 / 不适用+理由）

## 6. 需确认项
> 每条必须附「已查七路」的结果。案子里有、配置里有、历史答过的，**不许写进这张表**。
| 对象 | 问题 | 背景 | 已查七路（结果） | 建议默认值 |
|---|---|---|---|---|
（策划口径 / 客户端文案与渲染 / 运维配置）

### 6.1 客户端实测清单
（把最可能被客户端实测推翻的点列成可勾选清单：入口显隐条件是否与服务端同源 / 渲染表现 / 弹窗时机 / 双通道是否弹两次 / 退出路径在活动结束后是否可用）

## 7. 已知边界
（可接受的风险，写明理由；与线上既有功能行为一致时注明先例）

## 8. 覆盖率声明
需求条目：实测 M / 总数 N（按 RQ 计，不按"模块"计）
穷尽性：章节数 A / RQ 组 B（须相等）｜空列 K（须为 0）｜双向差异 P 条（须已列）
未实现 / 未验证 / 待外部输入：逐条列出
新增 RQ-new（验收过程中发现需求没写的）：N 条，已回流缺口清单
本次审了：…
没审：…（原因）
环境与版本：见 §0 环境指纹；结论不可直接外推到其他环境。
```

严重级别口径（与 SKILL.md 一致）：

- **P0**：玩家被卡住无反馈、看到与实际不符的状态、可重复刷奖励 / 绕过限制、任何分支（含异步 / 空入参）永远不回包、应答发错人。——阻塞上线。
- **P1**：反馈不完整（回包但字段缺）、状态不推送导致显示滞后、错误码客户端无文案、边界条件漏处理。——上线前必须处理。
- **P2**：提示文案、体验优化、冗余但不致命的重复推送。——可排期。
