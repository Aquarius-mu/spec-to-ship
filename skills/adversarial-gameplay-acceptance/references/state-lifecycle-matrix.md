# 状态生命周期矩阵（验收前置）

> **权威定义在 `game-feature-playbook`（开工时填）。** 本文件是验收侧的用法：
> 开工没填过，就在这里现填，并把它当作一条需求缺口记进 Q-xx。
>
> 来源：某大型活动功能验收，75 条记录、约 69 条真实问题。
> 归类后发现 74% 集中在五类，全部可在**验收前**用表格逼出来。

## 一、五类高频缺陷

| 类型 | 典型表现 | 根因 |
|---|---|---|
| 状态没定义完整 | 首次解锁显示"已满"；未开始就"已满"；重登后弹窗不见；升级后任务不完成 | 只实现正常在线操作 |
| ID 域混淆 | 取消 A 误取消 B；第二排头像错；两个对象等级算一起；按周取错配置 | 同名字段不同 id 域 / 用下标当 id |
| 上限口径不一 | 5/4 还能加；未到上限却不能打；15 级打不了 | 客户端/服务端/入口各一套 |
| 状态同步缺失 | 改完不刷新；失败后不刷新；多视图红点不一致；排行榜要重启 | 只写不推 / 只推一个场景 |
| 战报多源不一致 | 战力与阵容不符；缺公会信息；秒杀战报显示打 NPC | 多个生成点填充不全 |

## 四、验收前自测（逐条打勾）

**初始态**：新号 / 新赛季 / 首次解锁的显示值；未解锁时战报/频道/红点/入口是否隐藏；解锁链前置是否生效。

**边界**：0 / 1 / 上限-1 / 上限 / 上限+1；刚好跨天/跨周/新一轮；剩余时间 < 当天剩余。

**失败路径**：资源不足、兵力不足、被抢先、目标失效 → 回滚 + 提示 + 刷新。

**生命周期**：在线变更立刻可见；离线变更重登可见；进程重启数据完整；跨周期重置/结转正确。

**并发**：狂点；两个入口同时操作；取消 A 不影响 B。

**一致性**：多视图一致；列表与详情一致；客户端展示与服务端结算同源；战报与弹窗/排行榜一致。

**文本**：占位符全部替换（空值/0/最大值各一组）；中英文 id 对应、标点完整。

## 五、怎么用在验收报告里

- 每个状态字段在报告里占一行，写"矩阵已填 / 未填 / 不适用"。
- 未填的状态字段，验收结论只能是"未覆盖"，不能写"无问题"。
- 覆盖率声明里把"状态字段数"和"已填矩阵数"一起报，交给 `verify_report.py --coverage` 校验。
