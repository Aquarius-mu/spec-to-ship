# Bug 发生逻辑知识库

> 按"**怎么一步步变成 bug**"组织，用于事前拦截，而不是事后复盘。
> 与 `lessons.md` 的分工：lessons 是规则清单；本文是发生链条 + 防呆规则。

---

## 0. 一句话结论

**几乎所有 bug 都不是"写错一行"，而是四类链条之一：**

1. **事实源错**：没读原文/一手数据，用代码、记忆、旧快照、相似实现反推。
2. **生命周期断**：只做成功路径，离线/换轮/重启/失败/并发没有出口。
3. **配对不全**：做了"写"，没做"撤/退/清/推/去重"。
4. **验证失真**：回包=成功、日志=生效、抽样=全量、未部署=已修。

---

## 1. 事实源错（最高频）

### 发生链条

需求/配置存在权威源（需求文档、策划表、版本库、线上日志）→ 没读或只读片段 → 用代码现状/相似功能/旧版本/搜索结果补全 → 写出一个"自洽但与事实不符"的模型 → 被指出 → 返工。

### 典型表现

- 需求写了服务端编排自动战斗，做成客户端单队战斗。
- 排行界面漏了一列，因为只看了代码里已有的字段。
- 臆造配置键名，因为"按经验应该有"。
- 用最后一次提交的作者代替需求负责人。
- 属性映射就在协议结构里，却去问策划。

### 防呆规则

1. 动手前写"事实源清单"：需求 revision、表文件+列、分支、目标环境，各写一个可验证锚点。
2. 任何"与 XX 类似"的推断，先列差异表；差异表为空才允许参照。
3. 值必须可追溯：每个数值标"正文/表列/画板/评论/配置"来源；写不出来就进缺口。
4. 提问前跑七路检索（正文/画板/内嵌表/关联文档/配置/历史/代码），七路全空才问。
5. 用户口头澄清高于文档字面，写进已决台账并标日期。

## 2. 生命周期断（第二高频）

### 发生链条

只实现"在线、正常、一次成功" → 离线/重登/重启/换轮/跨天/并发/失败没有分支 → 状态卡死、重复发奖、漏发、永久停摆。

### 典型表现

- 状态机先写新状态再判等，后续副作用整段变成死代码。
- 请求上下文容器以自增序号为 key、只在回包时删除；离线实例不回包 → 容器无限增长直到 OOM。
- 待发队列在回包前清空；发奖函数返回值被丢弃。
- 重启跨过整个结算期，本轮奖励永不补发。
- 选主水印永不过期 + 两套让位判据 → 两台同时让位，永久停摆。
- 活动到期不清理队列/队伍/额度。

### 防呆规则

1. 每个可变状态填生命周期矩阵 10 时刻：初始、正常、边界、失败回滚、离线、重登、重启、跨周期、并发、多入口。
2. **先判定后写入**：比较当前状态的分支，禁止先覆盖再比较。
3. 每个容器/任务必须有非成功出口：超时、异常、下线、取消。
4. 写幂等键再发奖；键含对象 id + 轮次 + 事件 id；失败不置终态。
5. 启动期扫描未完成项，重启后补做；结算期跨越重启要能续办。

### 2.5 副本漂移（生命周期断的"空间版"）

### 发生链条

一个事实同时存在 缓存 / 共享存储 / 跨服快照 / 内部协议 / 客户端协议 / 战斗上下文 / 视图结构 多份 → 每份各自写入、各自采样、各自消费 → 展示、结算、跨服、客户端各看一份 → "客户端看到的不是服务器算的"。

### 典型表现

- 同一个增益：地图用占位快照、战斗用实时值；升级后快照不刷新。
- 视图函数为省流量裁剪快照字段 → 消费端补不出数据。
- 属性加成写在"组装战斗数据"之后 → 百分比没展开，战力少算；同时又写一份到另一容器 → 双算。
- 协议里有字段、写入侧没人赋值 → 详情永远空。
- 只改跨服结构没改客户端结构；改名只改一半；跨区用本区数据兜底 → 串号。

### 防呆规则

1. 每个跨模块字段先填表 0：权威源 / 副本落点 / 写入者 / 采样时点 / 刷新失效触发 / 消费口径。
2. 时效三选一：Live / Snapshot / Derived；一个字段只准一种，展示与结算必须同口径。
3. 快照必须有刷新触发；没有触发的快照 = 永久冻结。
4. 派生值先写齐所有加数再展开/汇总；同一属性只允许写入一个容器。
5. 全仓 grep 字段名，列全 写入/读取/序列化/跨服/下发 五类消费点；表里没有对应行 = 漏。

## 3. 配对不全（第三高频）

### 发生链条

新增"做"的动作（写入/扣费/报名/发奖/建对象/注册）→ 没有同时提交"撤/退/清/推/去重/删" → 状态残留、重复、泄漏。

### 典型表现

- 扣费成功、发奖失败直接返回；玩家重试再扣一次。
- 先落库后校验，失败不回滚，重复数据泄漏到跨服。
- 同一个奖励有三个领取出口（按钮/弹窗/补发），没有共用去重位。
- 撤防守不撤进攻镜像；自动补兵只补一队。
- 旧期实例判空缺失，遍历时全量扣除玩家当前持有量。
- 同一语义三处手写：轮次编码、排名、剩余数量公式。

### 防呆规则

1. 配对表：写入↔推送、扣费↔退款、报名↔撤报名、发奖↔去重、建↔删、注册↔注销、缓存↔落盘。
2. 每个"做"必须写失败路径与撤销路径；写不出就不算完成。
3. 单一事实源：编码、口径、结算键只允许一个函数生成，第二处手写即缺陷。
4. 幂等跳过分支不能漏清理；先校验后落库。
5. 改字段/协议后全仓搜读写点：写→读、旧值→新值、本进程→其它进程。

## 4. 协议与契约错

### 发生链条

先写代码后定契约，或契约多处维护 → 字段冗余/缺失、消息不配对、tag 冲突、客户端不知道。

### 典型表现

- 下发"即将开始"、总数、奖励预览、排行详情等客户端可算/可查字段。
- CS 失败只留日志、不回包；或框架回一次、handler 再回一次。
- 已落盘结构复用旧 tag 并改类型 → 反序列化失败、整个对象打不开。
- IDL 前向引用 → 生成器退出，编译用旧头文件。
- 消息文档与 IDL 漂移：幽灵字段、漏字段、错号。

### 防呆规则

1. 动作先于消息：先列玩家不可再分的动作，再定消息。
2. 六问：能否不开新消息；能否用子结构；多值是否写成单值；能否查表；能否推导；该放查询还是状态推送。
3. 每条 CS 每个分支恰好一条 SC；错误通道二选一，禁止两套同时回。
4. 已落盘结构 tag/类型不可改；未外放才可压实。
5. 文档↔IDL 跑对账脚本，零幽灵。

## 5. 跨服与并发错

### 发生链条

把单进程假设套到多进程 → 本区兜底、key 维度错、无配额、无锁、共享容器跨线程。

### 典型表现

- 视图裁剪快照字段，网关又用本区数据回查 → 阵容空/串号。
- 两端用不同周期拼 key → 活档被空档替换，大批对象未结算、玩家漏奖。
- 跨服派发无在途配额，单网关被打满。
- 用 A 分区缓存清全局，删掉 B 分区在途。
- RPC 线程直读分区状态并整表拷贝，主线程同时写入。

### 防呆规则

1. 先定层：网关 / 跨服(owner) / 归属服 / 驱动服，再取数。
2. key 由不可变身份唯一构造；可变维度不进主键。
3. 跨服禁止本区兜底、禁止裁剪快照字段、禁止跨库直写。
4. 派发必须有在途配额，所有退出路径成对释放。
5. 测试矩阵：2 网关 × 2 跨服 × 多分区 × 接管切换 × 离线回包；每分区恰一个存活 owner。

## 6. 配置与表错

### 发生链条

代码/表/分支只改一处 → 跨表引用悬空、缺列、主键重复、跨分支 cherry-pick 不带配置 → 启动失败/崩溃循环。

### 典型表现

- 删 sheet 未同步打表配置 → 生成器 abort。
- 主表加行未补属性表 → 打表失败。
- 合代码不带新字段 → 进程退出。
- 打表主键重复无预检。
- 配置缺失被打成 ERROR，告警洪泛。

### 防呆规则

1. 配置类外键必须"引用方 + 被引用方"成对提交。
2. 合并/回退前核对三件套：新增字段 → 目标分支表列 + 映射配置。
3. 打表前做全表主键唯一性校验，报文件/行/键。
4. 可降级配置缺失用 WARN，不用 ERROR；同区同族设抑制窗口。

## 7. 验证失真

### 发生链条

要交差 → 用"回包 ok / 日志有输出 / 命令返回 0 / 源码已改"当成功 → 不实测玩家路径 → 上线暴露。

### 典型表现

- 发布脚本某步失败仍打印 success；发奖失败仍扣积分。
- 源码已修但未部署 = FAIL。
- 只跑单账号/缺编队/机器人同名，冒充全量模拟。
- `make | tail` 吞掉编译错误；语法检查不校验 DOM。
- 空候选被当成"审查通过"。

### 防呆规则

1. 三路取证：消息回包原文 + 服务端收包日志 + GM/DB 回读。
2. 每条结论标 `[实测]` / `[推断]`；无环境才允许推断。
3. 全量结论必须给覆盖范围、总数、时间区间、样本外说明。
4. 验证工具必须与被测对象同源（同 revision、同部署、同环境）。
5. 修完必须复测原故障路径 + 同构路径。

## 8. 流程与上下文失控

### 发生链条

长任务无检查点 → 上下文丢失/超时 → 重读/重做/截断 → 结论片面或中断。

### 典型表现

- 长时间读案未落盘，中断后全丢。
- 大文件一次读满上下文，多个输出断裂。
- 改了规则未同步到全局 prompt；规则只在单次会话生效。
- 子代理截断仍报完成。

### 防呆规则

1. **增量落盘**：每 20 条需求/每 10 分钟写一次；大案禁止"读完再一次性生成"。
   - **只靠提示词不够**：即使明确要求"先写骨架"，agent 仍可能先读完全部载体、长时间无文件产出。
   - 必须**拆阶段**：阶段 1 只读正文并立即写骨架；阶段 2 读内嵌表并追加；阶段 3 读画板追加；阶段 4 读评论追加。每阶段独立调用，前阶段文件必须存在才进下一阶段。
2. 任务状态文件：阶段、进度、决策、待办，每阶段写回。
3. 分片用清单文件传递，不把大段内容塞进上下文。
4. 子代理输出必须完整 schema + 计数对账；截断即失败。
5. 规则改动同步到全局规则/skill，不只留在会话或记忆里。

## 9. 告警与运维错

### 发生链条

规则靠临场判断、没有机制闸 → 自造豁免 → 真实故障被合法放行；同时噪音白名单吞掉异常，告警群失去信号。

### 典型表现

- 已知误报的 return 已注释，仍按旧规则发卡。
- 跨服长时间不可用，被"责任主体未变更"规则挡在告警外。
- 长期噪音把真实异常一起淹没。
- 消息只要接口返回 ok 就登记 processed，不校验送达。

### 防呆规则

1. 规则落到可执行校验（fail-closed 闸），不靠临场判断。
2. 区分 sent / ack / handled；未 ack 要超时重发或人工兜底。
3. 白名单必须有期限与复核；噪音与故障用"是否中断加载/玩家可见"分层。
4. 依赖服务故障必须有独立告警与 owner。
5. 分发前做"换机可运行"检查，禁止硬编码本机路径。

## 10. 性能与容量错

### 发生链条

状态广播夹带全量数据、容器只增不减、无 TTL/配额 → 单点被打满或 OOM。

### 典型表现

- 状态广播带全量报名名单，网关为每个离线角色反复加载，CPU 与 RSS 暴涨。
- 请求上下文容器只增不减 → OOM。
- 跨服派发无在途配额，单网关被打满。
- 缓存无 maxmemory/TTL，发布目录不清理。

### 防呆规则

1. 状态广播只带增量或一次性数据。
2. 每个容器/队列必须有 TTL、容量上界、清理出口。
3. 派发有在途配额，所有退出路径成对释放。
4. 压测看三项：单机 CPU/RSS、超时条数是否持续增长、推进是否停摆。

## 11. 一次交付前的 12 问

1. 事实源清单写了吗？每个值能追溯吗？
2. 生命周期 10 时刻填了吗？
3. 每个"做"有"撤/退/清/推/去重"吗？
4. 幂等键维度全吗？失败会置终态吗？
5. 每条 CS 每个分支恰好一条 SC 吗？
6. 字段能说出客户端为什么不能自己算吗？
7. 跨服有本区兜底/裁字段/跨库直写吗？
8. 配置外键和跨分支三件套对了吗？
9. 改动范围外的文件动了吗？
10. 验证与被测对象同源吗？是全量吗？
11. 大任务有检查点吗？中断能续吗？
12. 交付表里每条有 `file:line` 和证据吗？
