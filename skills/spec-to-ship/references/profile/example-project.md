## 三、构建与发布

| 项 | 填什么 |
|---|---|
| 编译命令 | `make -j`（仓库根） |
| 产物路径 | `build/<Server>/<Server>` |
| 编译耗时 | 全量约 15–30 分钟，建议后台跑 |
| 谁来编译 | **用户执行**（团队约定，AI 不代跑） |
| 发布命令 | `./tools/deploy.sh --zone <zone>`；跨服加 `--cross` |

**判据**：不是看返回 0，而是看产物时间戳 / 进程 PID 变化。

## 四、协议层

| 项 | 填什么 |

## 六、日志（验收第一证据）

| 项 | 填什么 |
|---|---|
| 日志根路径 | `/var/log/examplegame/<zone>/<service>/` |
| 文件命名规则 | `<service>_<kind>_<date>.log` |
| 哪些 kind | `main` / `alarm` / `command` / `framework_error` |
| **服务端收到了什么** | `command` 日志的 `recv cmd:` |
| **客户端收到了什么** | 探针输出里的 `send response:`（**不是 command 日志**） |
| 怎么定位到某台机 | 按实例号查部署表；跨服日志在承载机 |

> 最容易踩的坑：把"收包日志"当"回包证据"。只看到收到，看不到回没回。

## 九、项目专有铁律

| # | 铁律 | 违反的后果 |
|---|---|---|
| 1 | 构建是 unity build，拆文件后必须补显式 include | 编译失败（不完整类型） |
| 2 | 删任何符号前全库 grep（含所有子目录） | 漏调用点，编译崩 |
| 3 | 已发布协议 tag / 类型不可改，删字段留墓碑 | 旧存档反序列化失败，整对象打不开 |
| 4 | 跨分区容器 key 必须带分区 id | A 分区玩家被塞进 B 分区的对象 |
| 5 | 索引从 0 起时注意与"0 = 未提供"哨兵冲突 | 第一个元素操作全被短路 |
| 6 | 部署/容量类数字读当前配置，不凭记忆 | 计划全错 |

（模式化清单见 `../codebase-pitfalls.md`）
