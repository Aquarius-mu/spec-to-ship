# 重档门禁细则（G0–G7）

> 只在重档（>20 条需求 / 跨服 / 发奖扣费 / 线上事故）时读本文件。中档按 SKILL.md 的简化版执行。

## 与 SKILL.md 七阶段的对应

| SKILL.md | 本文件 |
|---|---|
| ① 读案 | G0 锁案 |
| ② 需求清单 | G1 需求清单 |
| ③ 字段映射 | G1.5 字段映射（本文 G1 末段） |
| ④ 协议 | G3 协议先行 |
| ⑤ 实现 | G4 实现（细则见 `code-quality.md`） |
| ⑥ 自检+审查 | G2 开工定义 + G5 自审 |
| ⑦ 验收+交付 | G6 验收 + G7 交付 |

## G0 锁案

**输入**：飞书链接、代码根、范围、环境。

**做**：
1. wiki 链接先取 `obj_token`；读版本历史，记 revision 与读取日期。
2. 六类载体全读：正文（含 callout、折叠、删除线）、内嵌表/Base、画板/画格、正文图片（UI 截图）、评论区、修订历史。
3. 内嵌表逐档逐列誊抄，禁止"详见原表"。
4. 画板每个分支/箭头转成文字；纯图片画板导出后视觉读取。
5. 评论全部读取（含已解决），标出与正文冲突的条目。

**门禁**：六类载体都有记录；读不到的写原因。空章节逐条记缺口。

## G1 需求清单

**用**：`case-reader` agent（或按 `~\.claude\agents\case-reader.md` 规则手动执行）。

**产出**：`.tmpfiles/<功能>/需求规格.md`、`已决台账.md`、`缺口清单.md`。

**规则**：
- 编号 `R-xx` 永不复用；删除标"已删除"，修订出 diff。
- 每条写成可验收断言：`WHEN/WHERE → SHALL <行为>`，数值带来源锚点。
- 每条带"开发侧缺口"：消息、配置表字段、错误码、GM、日志。
- **增量落盘**：每 20 条 R-xx 写一次文件。50+ 章节、10+ 画板的大案子禁止"读完再一次性生成"。
- **评论优先**：评论出现"删掉/改成/应该是"时，按评论最新口径更新并标"经评论修正"。
- 模糊词（一些、尽量、合理、等）命中即进缺口。

**门禁**：每条 R-xx 有出处；空章节、矛盾、模糊词全标出；缺口清单每条附七路检索结果。

### G1.5 字段映射（凡案子画了界面/列了表头，必做）

| 案子字段 | 文本id | 协议字段 | 数据来源 | 结论 |
|---|---|---|---|---|
| 公会 | STRID_xxx | vRank[].sGuildName | stBaseInfo.sGuild | 已实现 |

- 数据来源写到具体结构体字段，不能写"已有接口"。
- **判据："缺"的行数必须为 0 才允许交付。**
- 只按代码现状补（"这里少个字段"）不算做过需求——先按案子列出的字段逐项核，再回代码找缺口。
- 实踩：排行榜玩法排行榜案子明列 6 列，直接读代码发现联盟为空就去补，没先对照案子，被指出"案子明明写了，为什么还是没有"。

## G2 开工定义

**用**：`game-feature-playbook`。

**五张表**：状态生命周期、ID 域、上限、变更→推送、消息契约。

**额外三件事**：
- 契约三方对齐：文档、客户端、配置表的索引基准（0/1 起）、周期、命名、枚举、号段。
- 单一事实源：榜单编码、排名口径、展示快照、结算键只允许一个生成函数。
- 配对表：写入↔推送、扣费↔退款、报名↔撤报名、发奖↔去重、cache↔落盘，每对写失败路径。

**门禁**：换个人只看五张表能实现得一样；写不出"谁读、用在哪"的字段删掉。

## G3 协议先行

**用**：`game-message-protocol`。

**规则**：
- 先问能不能不开新消息；客户端能算/查表/查榜的字段不下发。
- **客户端要读的进公共协议层，服务端自用的进内部数据结构层**（具体目录见 `profile/<项目>.md` §四）。
- 错误通道二选一：`return 非 0` 交给框架，或 handler 自己回 SC；禁止两套同时回。
- 已落盘结构 tag/类型不可改；未外放才可压实连续编号。
- IDL 无前向引用；删字段必须全库 grep 并同步改 C++。

**门禁**：CS 必回且仅回一条 SC；跑 `game-feature-playbook/scripts/audit_message_contract.py`，文档↔IDL 零幽灵。

## G4 实现

**顺序**：入口 → 准备 → 进行 → 结算 → 清理。

**硬规则**：
- 先判定后写入：任何比较当前状态的分支，禁止先覆盖再比较。
- 先校验后落库；客户端入参白名单。
- 状态四联动：写 cache + `setChanged` + push + 日志。
- 跨服禁止本区兜底、禁止裁剪快照字段、禁止跨库直写。
- 未外放不写迁移/兼容。
- 只改需求范围；改完 `svn st` 复核漂移。

**门禁**：每个写点回填表 1/表 4；空 handler 为 0；配对操作有撤销路径。

## G5 自审

- `game-code-review` 审代码质量与安全。
- 独立 agent A：逐条 `R-xx → file:line → 结论`，找漏实现和加戏。
- 独立 agent B：只看需求不看代码，按玩家旅程走一遍。

**门禁**：P0 清零；R-xx 每条有结论；三人冲突回案子原文裁决。

## G6 验收

**用**：`adversarial-gameplay-acceptance`。

- 有环境必须实跑，**四条铁证缺一即未跑**：CS 原文 / `commandstr` 的 `recv cmd` / SC 回包原文 / 字段判读。
- `commandstr` 是**收包**不是回包；只看它发现不了空回包。
- **空回包**：合法空须写依据；该有却空 = FAIL；无 `send response` = P0。
- 必查：生命周期 10 时刻、多身份交叉、跨进程通道、并发/重复、离线/重登/重启、跨周期。
- FAIL 走修复闭环：定位 → 改码 → 编译 → 发服 → 重测。
- 源码已修但未部署 = FAIL。

**门禁**：P0 清零；四条铁证齐；每条结论带 `[实测]`/`[推断]`。

## G7 交付

- 覆盖表：`R-xx → file:line → 验证方式 → 结论`，100% 行数。
- 待外部输入清单：表、文案、客户端字段、策划决策。
- 未验证项及原因。
- 文档回写飞书。
