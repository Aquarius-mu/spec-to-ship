# 执行路径：一条消息怎么跑完

> 本文回答：**我说"帮我完成案子，链接是 xxx"之后，到底按什么顺序、读哪个文件、调谁、产出什么。**
> 与 `workflow.md` 的区别：那份讲"每步做什么"，这份讲"每步读谁、调谁、交出什么文件"。

---

## 零、先理解"联调"是什么

**Skill 之间不会互相调用。** 没有运行时，没有编排引擎。真实机制：

```
启动时  → 所有 skill 的 name + description 预载进上下文
你说一句 → 拿你的话匹配 description
命中    → 才去读那个 SKILL.md 正文
正文说"读 X" → 再读 X
正文说"派 agent" → 调 Agent 工具
```

**没有人强制我去读下一步。** 所以每一环都必须在上一环的正文里写清楚"下一步读谁"——这就是本文存在的理由。

**真正的交接棒是文件**：
```
飞书 → 需求规格.md → 字段映射.md → IDL → 代码 → 审查报告 → 覆盖表
```

## 二、按档位裁剪

| 档 | 走哪些步 |
|---|---|
| **轻** | 2 → 10 → 14（简版） |
| **中** | 2 → 3–5 → 7 → 8 → 10 → 11 → 12 → 14 |
| **重** | 0–14 全套 |

判不了从中档起步。出现跨服/发奖/线上/数据迁移直接升重档。

## 三、每一步的"断了会怎样"

| 卡在 | 症状 | 大概率缺 |
|---|---|---|
| 第 0 步 | `check_deps` 报缺 | 没拷全（见 `porting.md`） |
| 第 3 步 | 说要读案但不知读什么 | `case-reader` agent |
| 第 5 步 | 需求清单没产出 | agent 超时——改增量落盘，每 20 条写一次 |
| 第 7 步 | 映射表全是"缺" | 全新功能，需先做第 8 步立协议骨架再回填 |
| 第 8 步 | 号段撞车 / IDL 解析失败 | `game-message-protocol` 没读 |
| 第 10 步 | 编译崩、代码被要求返工 | `codebase-pitfalls.md` / `code-quality.md` 没对照 |
| 第 12 步 | 审查只给空话、没有 file:line | 6 个 `code-review-*` agent 或 `review_setup.py` 缺 |
| 第 13 步 | "无法实测" | `adapter-*.md` 没按你的环境填 |

## 四、文件交接关系（谁产出、谁消费）

```
飞书文档 ──读──> 正文/表/画板/评论（临时）
                        │
                        ▼
             需求规格.md（R-xx）  ←── 消费方：③④⑤⑥⑦ 全部
             已决台账.md
             缺口清单.md
                        │
                        ▼
              字段映射.md  ←── 消费方：④ 协议设计、⑦ 交付对账
                        │
                        ▼
                  IDL / 代码
                        │
                        ▼
               审查报告 / 实测证据
                        │
                        ▼
                  覆盖表.md（R-xx → file:line → 结论）
```

**下游只读上游文件，不回头重读飞书。** 这是不重复劳动的关键。

---

## 五、异常分支

| 情况 | 怎么走 |
|---|---|
| 门禁没过但能自己补 | 补完重跑门禁，不前进 |
| 门禁没过需外部输入 | 记进 `PROGRESS.md` 未决 + `缺口清单.md`，做能做的部分 |
| 阻塞主流程 | 停下来报告，不硬推 |
| 中途中断 | 读 `PROGRESS.md`，从"当前阶段"续，不重读已完成 |
| 用户改需求 | 更新 R-xx（标修订 diff），回填受影响的表和映射 |

---

## 六、一句话

> **每步都有：读谁 → 调谁 → 产出什么 → 门禁是什么。**
> **说不出这四样，就是没在读流程，是在凭感觉干。**
