# 飞书案子一条链做完

读全 → 列清 → 定契约 → 写干净 → 自辩证 → 验到底 → 交覆盖表。

## 0. 换项目？先做这一步

这套流程分四层，**换代码库只动 L3/L4**：

| 层 | 内容 | 换项目 |
|---|---|---|
| L1 方法论 | 七阶段、进度声明、门禁、覆盖对账 | 不动 |
| L2 领域 | 客户端-服务端、离线/重连/跨进程、发奖扣费 | 不适用就删对应章节 |
| L3 技术栈 | 语言、构建、协议格式、日志、提交系统 | **填 profile** |
| L4 仓库 | 具体路径、表名、专有铁律 | **填 profile + pitfalls** |

迁移四步：

```bash
# 1 验依赖：这套流程要 6 个 skill + 7 个 agent + 2 个脚本同机
python scripts/check_deps.py

# 2 填画像
cp references/profile/_template.md references/profile/<新项目>.md
#    按 references/bootstrap.md 的五个 Step 逐项填

# 3 验画像
python scripts/check_profile.py references/profile/<新项目>.md   # 必须全 PASS
```

**依赖不齐 → 后面全白做**（清单见 `references/porting.md`）。
**画像没填实 → 回到凭猜**（填法见 `references/bootstrap.md`）。

## 0.5 选档（30 秒）

| 档 | 判据 | 走哪些 |
|---|---|---|
| **轻** | 单点改动、口述需求、hotfix | 出处 → 改 → 自测 → 交付 |
| **中** | 有案子、10–20 条需求、单进程 | 读案 → 需求清单 → 字段映射 → 实现 → 自检 → 审查 → 交付 |
| **重** | >20 条 / 跨服 / 发奖扣费 / 线上事故 / 多身份 | 全七阶段，细则读 `references/gates.md` |

判不了从中档起步；出现跨服、发奖、线上、数据迁移任一情形直接升重档。
用户说"小改一下""顺手修"默认轻档，不要反问要不要走全流程。

## 2. 代码质量铁律（返工主因，最高优先级）

> 用户原话："每次改出来的代码都要再优化一遍，问题很多。"
> 近百条返工反馈：要求精简 22 ｜ 要求优化 25 ｜ 可读性 13 ｜ 质量差 12。**不是写错，是写脏。**

1. **消息先做减法**：客户端能算/查表/查榜的字段一律不下发。典型该删的：倒计时提示（能换算）、列表总数（能数）、分页偏移（非真分页时）、返回码（走统一通道）、奖励预览（读表）、排行榜详情（查榜）、聚合计数（数列表）。具体字段名见 `references/profile/<项目>.md`。
2. **文件不要拆**：用户明确讨厌拆成多个小文件，按职责放进已有文件。
3. **头文件要减**：新增成员变量先答"谁读、读几次、能不能算"。读一次的不存，能算的不落盘，map key 已表达的不重复存。
4. **变量能省则省**，重复段落合并到一处。
5. **注释一句话、≤20 字、禁行尾**，写"为什么"不写"是什么"。
6. **改动按需求单全部提交**：按单号搜提交历史，找出**全部 revision**，不是只看最新 diff（命令见 `references/profile/<项目>.md` §五）。
7. **未外放就压实 tag**：删字段后重排 0..N，不留空号。
8. **禁止表面优化**：交付必须写清"删了什么/合并了什么/行数变化"，写不出就是没做。
9. **中文要地道**：不出现机翻式表达。

完整清单与证据：`references/code-quality.md`。

## 3. 各阶段要点

### ① 读案
六类载体全读，缺一即未完成：正文（含 callout/折叠/删除线）、内嵌表/Base、画板/画格、正文图片、评论区（含已解决）、修订历史。

- 内嵌表逐档逐列誊抄，禁"详见原表"
- 画板每个分支/箭头转文字；纯图片画板导出后看图
- **评论优先于正文**：出现"删掉/改成/应该是"按评论最新口径；实跑案子里 20 条评论有 5 条直接推翻正文
- 空章节 = 缺口，逐条记

### ② 需求清单
- 编号 `R-xx` 永不复用；删除标"已删除"，修订出 diff
- 每条可验收：`WHEN/WHERE → SHALL <行为>`，数值带来源
- **每 20 条增量落盘一次**，禁止读完再一次性生成
- 七路检索（正文/画板/内嵌表/关联文档/配置/历史/代码）没跑完不许问

### ③④⑤ 字段映射 / 消息协议 / 实现

**这三步读 `spec-driven-dev`**，不在这里重复：
- 第 2 节：字段映射表（案子字段 → 文本id → 协议字段 → 数据来源，"缺"必须为 0）
- 第 3–5 节：消息减法五问、操作码枚举、压实 tag、push 还是 Status
- 第 6–7 节：自动战斗四条、按玩家旅程实现

本 skill 只补两句这里特有的：
- 协议定义细节仍归 `game-message-protocol`；文档↔IDL 跑对账脚本，零幽灵
- 实现阶段同时对照 `references/codebase-pitfalls.md`（unity build、协议号、0 哨兵、跨区 key）

### ⑥ 自检 + 审查
1. 自评分 5 项（消息必要性 / 代码冗余 / 头文件与存储 / 注释 / 改动完整性），每项 0–2，<8 分先自己改
2. 独立 agent **证伪**：让它找"哪里还能删""哪里删错了"，不是问"对不对"
3. `game-code-review` 审质量与安全
4. **双 agent 派发方式见 `spec-driven-dev` 第 8 节**：
   - 需求覆盖 agent：逐条 `R-xx → file:line`
   - 玩家预演 agent：只看需求不看码，走一遍玩家旅程
5. 自己先当玩家走一遍（同 skill 第 9 节）

### ⑦ 验收 + 交付
- **四条铁证缺一条 = 没跑**：① 客户端发出原文 ② 服务端**收包**日志 ③ 服务端**回包**原文 ④ 字段判读
- **收包日志 ≠ 回包**；只看收包会永远发现不了"回包是空的"（本项目对应哪份日志见 profile §六）
- **空回包三分类**：合法空（须写依据）/ 异常空（FAIL）/ 无回包（P0）
- 三路交叉：回包 ≠ 状态生效 ≠ 玩家看到
- 每条结论标 `[实测]` / `[推断]`；源码已修但未部署 = FAIL
- 交付三件套：覆盖表 100% / 待外部输入 / 未验证项及原因

## 4. 一次性交付的定义

1. R-xx 每条有 `file:line + 验证方式 + 结论`
2. 字段映射表"缺"为 0
3. 协议对账零幽灵，CS/SC 配对完整
4. 编译通过（用户执行时如实记录）
5. 关键回包/状态/push 有实测证据
6. P0 清零，P1 有结论
7. 自评分 ≥8
8. 写着"删了什么/合并了什么/行数变化"
9. 文档回写完成
10. **12 问自证全过**（见下）

## 4.2 交付自证 12 问（说"完成"之前自己答完）

> 三个月 39 次追问全是在问这 12 件事。**任何一条答不上或拿不出证据，就不是完成。**
> 完整说明与真实原话见 `references/self-attestation.md`。

| # | 自问 | 证据 |
|---|---|---|
| 1 | 说改了的文件真改了吗 | 每个文件 diff 行数 + 一句改了什么 |
| 2 | 需求全实现了吗 | R-xx 覆盖表 100%，每行 `file:line` |
| 3 | 只跑消息还是跑了链路 | 每条 CS 的 ①发出 ②收包 ③回包 ④字段判读 |
| 4 | 依赖的改了吗 | 协议/表/配置/脚本/文档/另一进程 清单 |
| 5 | 离线玩家看得到吗 | push / Status / 首屏，三选一并说明 |
| 6 | 确认的问题修了吗 | 每个"确认是 bug"有对应 diff，**不许只确认** |
| 7 | 环境造全了吗 | 编队数/名字/公会/兵力/阶段 逐项核对 |
| 8 | 具体数值实现了吗 | 指到函数和分支，不说"应该实现了" |
| 9 | 上次说过的照做了吗 | 已决台账 D-xx 逐条对照 |
| 10 | skill 读了吗 | 进度头写明读了哪节 |
| 11 | 真跑十遍还是同一条跑十次 | 每轮输入/阶段/账号至少一项不同 |
| 12 | 每个"通过"有证据吗 | 挂 `file:line` / 回包片段 / 日志行 |

**第 1/2/3/12 问是硬门禁**：拿不出证据直接判未完成，不许进交付。

## 5. 禁止清单

- 用代码现状反推需求；只读片段就动手
- 把"注册了 handler / 加了字段"当实现；空 handler 留在代码里
- 兜底文本冒充功能；抽样冒充全量
- 先写状态再判等（副作用整段死代码）
- 发奖先置去重位再发；丢弃返回值；幂等键缺维度
- 扣费成功发奖失败不回滚；先落库后校验
- 跨服拿本区数据兜底
- 为过测试削校验；改需求范围外的代码
- 未外放功能写兼容/迁移
- 未验证就宣称完成
- 重复问已答过的问题

## 6. 失败即停

案子缺关键章节且阻塞主流程 / 数值冲突未裁决 / 代码根不确定 / 编译错误不在本轮改动 / 环境不可达且无法替代取证。
